پیشرفته: ساختار

دستورالعمل‌ها، گزینه‌های Choice، سطوح Score و معیارهای Noul همگی ساختار JSON می‌پذیرند.

آخرین به‌روزرسانی: مدل: jev-1.13.0 منبع بازبینی‌شده در منبع انگلیسی

مدل‌های System One برای فهم ساختار آموزش دیده‌اند. هر یک از فیلدهای زیر از نوع EntryType است:

فیلدبرایشکل مجاز
instructionsChoice، Score، Noulstring، object، array یا null
مقادیر criteria (توصیف گزینه‌ها)Choicestring، object، array یا null
اعضای criteria (توصیف سطوح)Scorestring، object، array یا null
criteria.true و criteria.falseNoulstring، object، array یا null

چه زمانی پرسش را ساختاریافته کنیم

  • وقتی به وضوح کمک می‌کند. وقتی پرسش چند بخش دارد، قالب JSON با کلیدهای برچسب‌دار شفاف‌تر است.
  • وقتی پرسش به داده‌ی پشتیبان نیاز دارد. یک schema، یک طبقه‌بندی (taxonomy) یا یک ردیف پایگاه داده از قبل JSON است؛ به‌جای جاگذاری در قالب رشته، خودش یا زیرفیلدهای مرتبطش را بفرستید.

پیمایش یک طبقه‌بندی (taxonomy)

برای طبقه‌بندی در یک طبقه‌بندی عمیق، در هر سطح یک Choice بپرسید و درخت را در کد پیمایش کنید. در هر گام گزینه‌ها فرزندان گره‌ی فعلی‌اند و مقدار هر گزینه، زیردرخت آن فرزند است. این‌طور مدل پیش از انتخاب یک شاخه می‌بیند زیر آن چه چیزی هست. probabilities پاسخ به شما می‌گوید آیا رقابت به‌اندازه‌ای نزدیک است که هر دو شاخه را بررسی کنید.

زیردرخت‌ها ممکن است بزرگ شوند. اگر شاخه‌ای خیلی بزرگ است، مقدارش را به فرزندان مستقیم و نمونه‌ای از برگ‌ها محدود کنید.

سطوح ساختاریافته‌ی Score و معیارهای Noul

هر عضو آرایه‌ی criteria در Score می‌تواند یک شیء باشد (توصیف به‌علاوه‌ی چند موقعیت نمونه). در Noul، وقتی مرز بله/خیر ظریف است، توصیف‌های ساختاریافته‌ی true و false اجازه می‌دهند آن را با تعریف و مثال در هر دو سمت دقیق کنید.
