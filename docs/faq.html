سؤالات متداول FAQ

پاسخ کوتاه سؤالاتی که بیشتر درباره‌ی Jev و همین سایت (جِو هاب) پرسیده می‌شود. برای جزئیات بیشتر هر بخش، به صفحه‌ی مرتبط مستندات مراجعه کنید.

آخرین به‌روزرسانی: مدل: jev-1.13.0

این صفحه بخشی از مستندات رسمی TypeSafe نیست؛ جمع‌بندی غیررسمی جِو هاب از پرتکرارترین سؤالات است. برای مرجع قطعی هر مورد، همیشه به مستندات رسمی لینک داده شده.

کلیات

Jev دقیقاً چیست و با ChatGPT چه فرقی دارد؟

Jev مدل پرچم‌دار و اولین مدل System One شرکت TypeSafe است. برخلاف ChatGPT یا هر LLM دیگری که برای تولید متن آزاد جهت خواندن انسان طراحی شده، Jev به چند پرسش تایپ‌شده (Choice، Score، Noul) روی یک state پاسخ می‌دهد — پاسخی ساختاریافته، با احتمال و اطمینان کالیبره‌شده، که کد شما مستقیم روی آن شاخه می‌زند. برای جزئیات بیشتر صفحه‌ی System One را ببینید.

آیا Jev از زبان فارسی پشتیبانی می‌کند؟

بله، می‌توانید state و instructions را به فارسی بفرستید. اما طبق مستندات رسمی، Jev بهترین دقت و کالیبراسیون را روی متن انگلیسی دارد. اگر ورودی‌های اصلی شما فارسی‌اند، پیش از استقرار حتماً روی داده‌ی واقعی خودتان تست کنید و به مقدار confidence توجه ویژه‌ای داشته باشید — چند مثال این صفحه (مثل «دستیار صوتی بانکی») دقیقاً همین نکته را یادآوری می‌کنند.

جِو هاب رسمی TypeSafe است؟

خیر. جِو هاب یک ترجمه و بازنویسی فارسی غیررسمی از مستندات Jev است، ساخته‌شده توسط یک توسعه‌دهنده‌ی مستقل. محتوا بر اساس مستندات رسمی TypeSafe تهیه شده و در صورت هرگونه اختلاف، نسخه‌ی رسمی انگلیسی معتبر است. برای حساب کاربری، صورت‌حساب، کلید API یا هر چیز مربوط به سرویس واقعی، به کنسول رسمی TypeSafe مراجعه کنید.

فنی

آیا می‌توان Jev را self-host یا آفلاین اجرا کرد؟

خودِ Jev فقط از طریق API ابری TypeSafe در دسترس است؛ نسخه‌ی خودمیزبان رسمی وجود ندارد. اگر دنبال جایگزین متن‌باز و قابل self-host می‌گردید (مثلاً برای داده‌ی حساس یا اجرای آفلاین)، صفحه‌ی جایگزین‌ها چند گزینه از جمله Von را معرفی می‌کند که ادعا می‌کند با همان API سازگار است.

تفاوت Choice، Score و Noul چیست؟ کدام را استفاده کنم؟

Choice یک گزینه از فهرستی که خودتان تعریف می‌کنید انتخاب می‌کند (مثل دسته‌بندی تیکت). Score روی سطوح مرتب و توصیفی رتبه می‌دهد (مثل شدت یک باگ، از خفیف تا مسدودکننده). Noul یک پرسش بله/خیر است که احتمال «بله» را برمی‌گرداند (مثل «آیا این پیام فوری است؟»). قاعده‌ی سریع: اگر گزینه‌های مشخصی دارید → Choice؛ اگر یک طیف مرتب دارید → Score؛ اگر پرسش دوتایی است → Noul. جزئیات کامل در مرور پرسش‌ها.

چرا Jev را به‌جای JSON mode مدل‌های دیگر (مثل OpenAI Structured Outputs) استفاده کنم؟

JSON mode یک LLM معمولی همچنان یک مدل تولیدکننده‌ی متن اتورگرسیو است که فقط شکل خروجی‌اش محدود شده — کند‌تر برای چند پرسش هم‌زمان، و بدون احتمال کالیبره‌شده‌ی آماده. Jev یک مدل System One جداگانه است که مستقیم برای همین کار (تصمیم‌های تایپ‌شده و موازی، با اطمینان کالیبره‌شده) آموزش دیده. اگر می‌خواهید مقایسه‌ی دقیق‌تری ببینید، جدول کامل در صفحه‌ی جایگزین‌ها هست.

آیا Jev می‌تواند متن تولید کند (مثل نوشتن پاسخ ایمیل)؟

نه، Jev برای تولید متن آموزش ندیده — طبق محدودیت‌های شناخته‌شده‌ی Jev 1.13، این یکی از مواردی‌ست که باید از یک مدل مولد معمولی (LLM) استفاده کنید. کاربرد Jev قضاوت و تصمیم‌گیری تایپ‌شده روی محتوای موجود است، نه تولید محتوای جدید.

اگر مدل پاسخ اشتباه بدهد چه کنم؟

اول به confidence پاسخ نگاه کنید — اگر پایین بود، مدل خودش عدم‌قطعیت را نشان داده و کد شما باید به‌جای اقدام خودکار، به انسان ارجاع بدهد (الگوی مسیریابی با آستانه‌ی اطمینان). اگر با اطمینان بالا اشتباه پاسخ داده، احتمالاً دستورالعمل یا معیارهای Choice/Score شما مبهم یا قابل چند برداشت است؛ فهرست حالت‌های شکست شناخته‌شده و راه‌حل هرکدام در محدودیت‌های Jev 1.13 آمده.

هزینه و محدودیت‌ها

هزینه‌ی استفاده از Jev چقدر است؟

Jev بر اساس توکن ورودی قیمت‌گذاری می‌شود (فعلاً حدود $۰٫۰۴۲ به ازای هر میلیون توکن ورودی، با خروجی رایگان — عدد دقیق و به‌روز را در صفحه‌ی اصلی یا مدل‌ها و قیمت ببینید). چون همه‌ی پرسش‌های شما در یک درخواست موازی ارزیابی می‌شوند، افزودن پرسش‌های بیشتر هزینه و زمان پاسخ را تقریباً افزایش نمی‌دهد.

محدودیت نرخ (rate limit) چطور کار می‌کند؟

اگر از محدودیت نرخ بگذرید، خطای 429 Too Many Requests می‌گیرید؛ اگر سرویس موقتاً پربار باشد 529 Overloaded. در هر دو حالت باید با exponential backoff دوباره تلاش کنید — SDKهای رسمی این کار را به‌طور پیش‌فرض خودکار انجام می‌دهند. جزئیات کامل در خطاها و محدودیت نرخ.

داده‌های state من کجا ذخیره می‌شود و چقدر امن است؟

این سؤال باید از مستندات رسمی و شرایط استفاده‌ی TypeSafe پاسخ داده شود، نه از جِو هاب — این‌جا یک ترجمه‌ی غیررسمی است و هیچ دسترسی یا اطلاعی از زیرساخت واقعی TypeSafe ندارد. برای داده‌ی حساس که نباید خارج از زیرساخت خودتان برود، صفحه‌ی جایگزین‌ها گزینه‌های خودمیزبان را نشان می‌دهد.
