State

state چیست، چگونه ساختارش دهیم و چطور کانتکست لازم را به مدل System One بدهیم.

آخرین به‌روزرسانی: مدل: jev-1.13.0 منبع بازبینی‌شده در منبع انگلیسی

State محتوایی است که از مدل System One می‌خواهید ارزیابی‌اش کند. می‌تواند یک پیام پشتیبانی، یک بند متن یا وضعیت فعلی اپلیکیشن شما باشد. آن را در فیلد state درخواست API و کنار پرسش‌هایی که می‌خواهید پاسخ داده شوند می‌فرستید.

هر درخواست یک state را در برابر یک یا چند پرسش ارزیابی می‌کند. همه‌ی پرسش‌ها همان state را می‌بینند و مستقل ارزیابی می‌شوند.

state می‌تواند رشته‌ی ساده یا مقدار JSON ساختاریافته باشد

ساده‌ترین state یک رشته است: state = "My card was charged twice."

state همچنین می‌تواند یک شیء یا آرایه‌ی JSON شامل کانتکست مرتبط، مثال‌ها و سایر اطلاعاتی باشد که به مدل در پاسخ به پرسش‌ها کمک می‌کند. state را مثل مطالبی تصور کنید که پیش از درخواست قضاوت، جلوی یک هیئت متخصص می‌گذارید.

قالبمناسب برایمثال
رشتهیک پیام، مقاله یا بند متن"My card was charged twice."
شیءفیلدهای نام‌دار، رکوردهای مرتبط یا وضعیت اپلیکیشن{"message": "My card was charged twice.", "order_id": "A-104"}
آرایهدنباله‌ای از پیام‌ها یا رکوردها["Hi", "My customer number is TS1337.", "My card was charged twice."]

برای بیشتر درخواست‌ها از شیء استفاده کنید تا هر بخش state نامی توصیفی داشته باشد و روابط روشن بماند. رشته برای موارد ساده‌ای مناسب است که فقط یک تکه متن لازم دارند.

زبان اصلی آموزش Jev انگلیسی است؛ زبان‌های دیگر، از جمله فارسی، پذیرفته می‌شوند اما در حال حاضر دقت کمتری دارند. پیش از اتکا به Jev برای محتوای غیرانگلیسی، روی داده‌ی خودتان آزمایش کنید (مدل‌ها ← پشتیبانی زبان).

این شیء یک state است، هرچند شامل یک گفت‌وگو، یک سفارش و یک سیاست است. وقتی تصمیم به مقایسه‌ی این بخش‌ها نیاز دارد، اطلاعات مرتبط را کنار هم بگذارید.

محتوا را از پرسش‌ها جدا کنید

state شامل محتوا و واقعیت‌های پشتیبان است. پرسش‌ها قضاوت‌هایی را تعریف می‌کنند که مدل باید درباره‌ی آن محتوا انجام دهد. مثلاً درخواست بازپرداخت و سیاست را در state نگه دارید، سپس بپرسید آیا مشتری بازپرداخت خواسته و آیا سیاست از آن پشتیبانی می‌کند.
