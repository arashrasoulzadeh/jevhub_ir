# جِو هاب — مستندات فارسی Jev

سایت ایستا (HTML/CSS/JS خالص، بدون نیاز به build) برای مستندات فارسی مدل Jev از TypeSafe.

## اجرا

```bash
python3 dev-server.py
```

سپس `http://localhost:8765` را باز کنید. از این سرور به‌جای `python3 -m http.server` استفاده کنید — هدر `Cache-Control: no-store` می‌فرستد تا موقع ویرایش، مرورگر نسخه‌ی قدیمی فایل‌های JS/CSS را کش نکند (یک بار همین موضوع باعث یک باگ گیج‌کننده شد).

### اجرا با Docker

روی یک سرور شلوغ، اول یک پورت آزاد پیدا کنید:

```bash
ss -ltn   # یا: netstat -nltp
```

مقدار `APP_PORT` را در `.env` به همان پورت آزاد تغییر دهید (پیش‌فرض `8088`)، سپس:

```bash
docker compose up -d --build
```

سپس `http://<سرور>:<APP_PORT>` را باز کنید. تصویر با nginx محتوای استاتیک را سرو می‌کند (`Dockerfile` + `docker/nginx.conf`)؛ کانتینر همیشه داخلش روی پورت ۸۰ گوش می‌دهد، فقط پورت سمت هاست از `APP_PORT` می‌آید.

## تنظیمات (`.env`)

`SITE_URL` (دامنه‌ی کامل سایت) و `GA_MEASUREMENT_ID` (شناسه‌ی Google Analytics) از فایل `.env` در ریشه‌ی پروژه خوانده می‌شوند — نه هاردکد در کد. برای شروع:

```bash
cp .env.example .env
```

بعد از تغییر مقادیر در `.env`، اسکریپت‌های `.build-scripts/` را دوباره اجرا کنید تا در همه‌ی ۲۹ صفحه اعمال شود (بخش «بازتولید همه‌ی صفحات» را ببینید). این تنظیمات فقط زمان **تولید** فایل‌های HTML استاتیک استفاده می‌شوند؛ کانتینر Docker فایل‌های از‌پیش‌ساخته را فقط سرو می‌کند و در زمان اجرا `.env` را نمی‌خواند.

## ساختار

| مسیر | کاربرد |
| --- | --- |
| `index.html` | صفحه‌ی اصلی با دموی زنده و معرفی |
| `docs/index.html` | فهرست مستندات (هاب) |
| `docs/<slug>.html` | **۲۶ صفحه‌ی مستقل مستندات** — هرکدام با `<title>`، توضیح متا، H1 و URL جداگانه (برای سئو)؛ هرکدام تاریخ و نسخه‌ی مدل خودش را نشان می‌دهد |
| `docs.html` | ریدایرکت قدیمی به `docs/index.html` (برای لینک‌های قبلی) |
| `examples.html` | گالری مثال‌ها با فیلتر، جست‌وجو و کشوی جزئیات |
| `sitemap.xml`, `robots.txt` | برای سئو — پیش از دیپلوی دامنه‌ی واقعی را در `sitemap.xml` جایگزین `your-domain.example` کنید |
| `assets/js/config.js` | **تاریخ به‌روزرسانی مستندات** و نسخه‌ی مدل |
| `assets/js/examples-data.js` | **داده‌ی مثال‌ها** |
| `assets/js/main.js` | تم، انیمیشن‌ها، هایلایت کد، ویجت‌های تعاملی، منطق سایدبار/TOC مستندات |
| `assets/css/style.css` | استایل‌ها (تم تیره/روشن) |

## ساختار صفحات مستندات

هر صفحه‌ی `docs/<slug>.html` کاملاً مستقل است و برای سئو بهینه شده:
- `<title>`, meta description, `<h1>` و canonical مخصوص خودش
- Open Graph, Twitter Card و JSON-LD (`TechArticle` + `BreadcrumbList`) مخصوص خودش
- تگ Google Analytics (gtag.js)
- سایدبار کامل با لینک به همه‌ی صفحات دیگر (لینک صفحه‌ی فعلی هایلایت می‌شود)، TOC سمت راست مخصوص همان صفحه، و pager قبلی/بعدی

### ویرایش محتوای یک صفحه

مستقیماً همان فایل `docs/<slug>.html` را ویرایش کنید — این فایل‌ها منبع اصلی (source of truth) محتوا هستند.

### بازتولید همه‌ی صفحات (`.build-scripts/`)

دو اسکریپت پایتون در `.build-scripts/` صفحات را از روی محتوای فعلی `docs/*.html` دوباره می‌سازند (idempotent — هربار از خروجی اجرای قبلی می‌خوانند):

```bash
python3 .build-scripts/rebuild_docs.py   # بازسازی هر ۲۶ صفحه با شل (سایدبار/فوتر/سئو) یکسان
python3 .build-scripts/gen_docs_index.py # بازسازی docs/index.html از روی صفحات بالا
```

از این‌ها وقتی استفاده کنید که شِل مشترک صفحات را تغییر می‌دهید (مثلاً چیزی به هدر یا فوتر اضافه می‌کنید) — محتوای هر بخش دست‌نخورده می‌ماند چون از خودِ `docs/*.html` خوانده می‌شود، نه از یک منبع دیگر. برای افزودن یک زیربخش (`<h3>`) به یک صفحه‌ی موجود، مستقیم همان فایل را ویرایش کنید و نیازی به اجرای اسکریپت نیست.

### پیوندهای داخلی بین صفحات

از آنجا که هر صفحه فایل جداست، پیوند به بخش دیگری از مستندات باید به‌صورت `<a href="slug.html">` یا `<a href="slug.html#heading-id">` باشد، نه `#slug`. اگر اسکریپت split اولیه دوباره اجرا شود روی محتوای تک‌فایلی قدیمی، این تبدیل خودکار انجام می‌شود؛ هنگام ویرایش دستی، خودتان این قانون را رعایت کنید.

## افزودن مثال جدید

یک شیء به انتهای آرایه‌ی `window.JEV_EXAMPLES` در `assets/js/examples-data.js` اضافه کنید. الگوی کامل فیلدها (شامل `sourceUrl` اختیاری برای ارجاع به cookbook رسمی) در ابتدای همان فایل آمده است. مثال به‌صورت خودکار در صفحه‌ی مثال‌ها (و اگر جزو سه مثال آخر باشد، در صفحه‌ی اصلی) نمایش داده می‌شود و از آدرس `examples.html#<id>` در دسترس است.

## به‌روزرسانی تاریخ مستندات

در `assets/js/config.js` مقدار `docsUpdated` (و در صورت نیاز `sourceReviewed`) را به تاریخ میلادی `YYYY-MM-DD` تغییر دهید؛ همه‌جای سایت (هر ۲۶ صفحه) به‌صورت خودکار به تاریخ شمسی نمایش داده می‌شود. برای اینکه تاریخ `dateModified` در JSON-LD هم به‌روز شود، `.build-scripts/rebuild_docs.py` را دوباره اجرا کنید (این مقدار را مستقیم از همین فایل می‌خواند).

## Google Analytics

شناسه‌ی اندازه‌گیری (`G-QV7SENV5V1`) در هر ۲۹ صفحه جاسازی شده. برای تغییرش، مقدار را هم در `.build-scripts/rebuild_docs.py` (متغیر `GA_SNIPPET`) و `.build-scripts/gen_docs_index.py` تغییر دهید و دوباره اجرا کنید، و در `index.html` / `examples.html` هم دستی جایگزین کنید (این دو فایل توسط اسکریپت تولید نمی‌شوند).

## قبل از دیپلوی

در `sitemap.xml` و در متغیر `SITE_URL` هر دو اسکریپت `.build-scripts/*.py` (و در `<link rel="canonical">` / تگ‌های `og:url` داخل `index.html` و `examples.html`) مقدار `your-domain.example` را با دامنه‌ی واقعی جایگزین کنید.
